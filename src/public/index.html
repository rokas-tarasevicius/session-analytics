Data coverage

Every number on the dashboard is a lower bound built from local evidence. This panel lists what the current selection can and cannot establish.

Coverage notes

    What the local history can tell you

    Coverage is sessions with evidence / selected sessions. Summary and activity-only sources cannot establish all metrics. Unavailable is shown as a dash, never as zero activity. Counts do not prove success or quality.

    ProviderSourceFidelitySessionsToken evidenceTool evidenceTime basis

    How to read these numbers

    • Activity dates use the snapshot timezone, as in Velocity. The chart includes dated value, and session-dated value from sources without request times on the session's last activity day; undated value, such as Cursor's provider-reported value, and sessions without velocity evidence remain outside the chart. The usage-value KPI, repository values, the fleet table, Costs, Pricing, Velocity and the daily CSV export all use this same ledger. Not an invoice.
    • Usage value and Priced: activity-dated ledger for the window, so the rows add up to the Usage value KPI. Other columns: sessions started in the window.
    • API-equivalent value is a list-price equivalent of observed tokens, not an invoice. Provider-reported value is kept separate.
    • Coverage badges such as 87/116 show how many selected sessions carry the evidence behind a number; hover one for the sentence.
    • Request input includes repeated context; the cached share measures recorded cache reads.
    • Ratios with tiny denominators are withheld; a dash means not applicable, never zero.
    • Activity counters do not prove success, quality, or value delivered.
    • Agents on a server or VM too? Run session-analytics machines add HOST in a terminal, and every later scan reads that machine with this one. Combine machines ↗
